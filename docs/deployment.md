# Deployment

Deploy each application in its own wrapper, for example `/var/www/<project>/backend`, with a project-owned Compose file and runtime directory one level above. RachVision-owned templates can remain under the established RachVision server root. Client applications belong under the separately restricted client root. They must not share volumes, credentials, networks, auth cookies, backup repositories, or Compose project names.

Copy `compose.example.yml` to the project wrapper and adapt paths and limits. Bind PocketBase to an assigned loopback port or private container network. Put Caddy or another reverse proxy in front only where the application contract requires it. Administration should use an SSH tunnel.

`docker.sh` refuses dirty checkouts and non-fast-forward updates. It compares the incoming revision with the last successfully deployed revision before moving the checkout. If migrations changed, it requires either an explicitly declared first install or a non-empty valid PocketBase backup ZIP at an absolute path. The deployed-revision marker advances only after the container becomes healthy, so a failed release cannot bypass the backup gate on retry. PocketBase applies pending migrations at startup even when automatic migration generation is disabled. Keep the previous image and matching data snapshot for rollback.

## Environment

Configure the variables documented in `.env.example` through the project's private Compose environment (`compose.example.yml` passes all of them). Runtime settings are re-applied at every start; an invalid value stops the container before it becomes healthy. Never run `corepack yarn seed` against a deployed instance; it refuses non-local app URLs.

| Variable                                       | Production value                    | If unset                                                                                                                                                                                                         |
| ---------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PB_ENCRYPTION_KEY`                            | 32-character secret                 | Settings (including the SMTP password) are stored unencrypted.                                                                                                                                                   |
| `PB_SUPERUSER_EMAIL` / `PB_SUPERUSER_PASSWORD` | Recovery account                    | Only read by the foundation migration on a fresh database.                                                                                                                                                       |
| `PB_TRUSTED_PROXY_HEADERS`                     | `X-Forwarded-For` behind Next.js    | **All users share the gateway IP for rate limits** (10 logins per minute, 3 reset emails per 15 minutes, 300 requests per 10 s for everyone). A startup warning is logged. Once applied, the value stays stored. |
| `PB_APP_URL`                                   | Public frontend origin              | Email links keep the stored app URL (`http://localhost:8090` on a new database) and are broken for users.                                                                                                        |
| `PB_APP_NAME`                                  | Product name                        | Emails keep the stored name (`PocketBase backend template`).                                                                                                                                                     |
| `PB_REGISTRATION_ENABLED`                      | `true` to allow sign-up             | Registration and guest upgrades return `403`.                                                                                                                                                                    |
| `PB_REQUIRE_EMAIL_VERIFICATION`                | `true` once SMTP works              | Unverified accounts can sign in.                                                                                                                                                                                 |
| `PB_GUEST_ENABLED`                             | `true` to offer "continue as guest" | Guest creation returns `403`; existing guests still expire.                                                                                                                                                      |
| `PB_GUEST_TTL_HOURS`                           | `24` (default)                      | Guests live 24 hours.                                                                                                                                                                                            |
| `PB_SMTP_*`, `PB_MAIL_SENDER_*`                | Provider settings                   | Stored SMTP settings stay unchanged (disabled on a new database): no verification, reset, or login alert emails are delivered.                                                                                   |

After release, verify the health and config routes, migration state, representative records and files, authentication, the public application path, backup coverage, and unrelated applications on the host.
